# v0.9.0 Threat Model, Data Classes, and Permission Enforcement

Status: ordinary-development security vocabulary for v0.9.0  
Issue: [#1093](https://github.com/jasonhnd/loopcoder/issues/1093) (`V090-084`)  
Platform: `darwin/arm64` only  
Companion code: [`internal/securitypolicy`](../../internal/securitypolicy)

This document is the accepted security vocabulary for later foundation work
(`V090-085`, `V090-003`, and the direct-run path). It inventories trust
boundaries, data classes, capabilities, existing enforcement owners, and open
gaps. It does **not** create credentials, a sandbox product, or provider-specific
policy.

## 1. Trust stance

LoopCoder is a local single-operator CLI. The operator chooses the repository,
provider CLIs, network, and host. That does **not** make inputs safe.

### Explicitly untrusted inputs

These inputs must never become authority for immutable route, permission, base
branch, project identity, or effective-policy snapshots:

| Input | Why untrusted |
| --- | --- |
| GitHub issue / PR body and comments | Attacker-controlled text and prompt injection |
| Repository files, symlinks, hooks, and Git config | Writable by workers and prior commits |
| Provider stdout/stderr and model text | Untrusted process output |
| Host/UI messages and acknowledgements | Forgable unless protocol-authenticated |
| Recovered local records after crash | May be truncated, stale, or partially written |
| Inherited process environment | May poison `GIT_*`, credentials, or path search |
| Optional review bots (for example Greptile) | Optional evidence only; not merge authority |

### Trusted only when explicit and frozen

| Authority | Source of trust |
| --- | --- |
| Operator intent | Explicit CLI/run pins for provider, model, effort, permission, base, and report clients |
| Effective policy snapshot | Versioned configuration freeze before side effects (`V090-085`) |
| Deterministic policy code | Built-in fail-closed gates after validation |
| Durable project identity | Machine/project registry after registration, not folder display names |
| Protected remote evidence | Required CI contexts and release artifacts (see [`../reference/evidence-tiers.md`](../reference/evidence-tiers.md)) |

## 2. Assets

- **Credentials:** API keys, OAuth tokens, cookies, SSH keys, provider auth files,
  keychain material, secret-bearing environment values.
- **Private content:** source, issue text, prompts, provider transcripts, local
  absolute paths, account labels.
- **Authority records:** route pins, permission mode, base revision, project id,
  effective-policy digest, claims, approvals, idempotency keys.
- **Process integrity:** supervised child trees, worktree isolation, cancellation.
- **Release evidence:** check SHAs, archive digests, GO/NO-GO records.

## 3. Data classes

Every v0.9 field that is persisted, rendered, logged, or exported must declare
exactly one class. Package `securitypolicy` mirrors these identifiers.

| Class ID | Meaning | Allowed scope | Retention owner | Default redaction |
| --- | --- | --- | --- | --- |
| `credential` | Secret material usable for auth | Never persisted by LoopCoder; never rendered | Operator / provider CLI / OS keychain | Full suppress; fail if observed in product records |
| `private_content` | Issue text, source excerpts, prompts, raw provider output | Local project DB / logs only under explicit run ownership | Project store + log retention (`V090-087`) | Summarize or drop in PR/chat/export; `sanitize.Text` before any render |
| `operator_report` | Bounded human/JSON progress reports | Local UI stream + project events | Project events / UI ack ledger | Redact paths and secrets; no raw transcripts by default |
| `raw_log` | Unbounded process output files | Local log directory only | Project log retention | Never copy into PR/issue/commit; redact if sampled |
| `path_local` | Absolute or user-home paths | Local diagnostics only | Ephemeral or hashed identity | Replace with `[REDACTED_PATH]` or `pathid` identity hash |
| `route_evidence` | Provider/model/effort/permission pins, decision codes | Project events and status projections | Project store | Public codes allowed; no credentials |
| `quota_observation` | Quota/budget observations with provenance | Machine authority snapshots | Machine store | No account secrets; mark `unknown` when unauthoritative |
| `public_metadata` | Issue numbers, PR numbers, SHAs, check names, versions | Anywhere including PR bodies and release notes | GitHub / release artifacts | None required beyond accuracy |
| `synthetic_fixture` | Test-only identities and tokens | Test temp directories and fixtures | Test process lifetime | Must never equal real credentials |

### Field inventory for the v0.9 direct path

The direct path does not yet implement every field. This table freezes the class
assignment so schemas and report renderers cannot invent weaker classes later.

| Surface / field family | Class | Notes |
| --- | --- | --- |
| Provider API keys / auth files | `credential` | Out of LoopCoder storage |
| Issue title/body used as prompt context | `private_content` | Untrusted content |
| Worker/provider transcript files | `raw_log` | Local only |
| Five-minute / terminal report `summary` | `operator_report` | Bounded + sanitized |
| Report `last_evidence` pointers (PR, SHA, check) | `public_metadata` or `route_evidence` | Prefer IDs over paths |
| Worktree absolute path | `path_local` | Hash or relative in exports |
| Selected provider/model/effort/permission | `route_evidence` | Frozen at run start |
| Base branch / base SHA | `route_evidence` | Immutable for attempt |
| Project id / GitHub owner/repo | `public_metadata` | After registry normalization |
| Quota remaining / reset windows | `quota_observation` | Provenance required |
| CI check name + conclusion + SHA | `public_metadata` | Required-check discovery |
| Archive digest | `public_metadata` | Release evidence |
| UI client id + ack stage | `operator_report` | Forged ack is a threat (gap below) |
| Fixture tokens / fake issues | `synthetic_fixture` | Harness only (`V090-003`) |

## 4. Capability model (deny by default)

Capabilities are required before any mutation or external side effect. An
unmapped capability is **denied**. Package identifiers:

| Capability | Side effects allowed | Enforcement owner (existing or planned) |
| --- | --- | --- |
| `cap.read_repo` | Read repository and issue metadata | Caller + `readonlyexec` when child must not mutate |
| `cap.bounded_write` | Write only declared paths in an isolated worktree | `writeexec` |
| `cap.network_provider` | Invoke provider CLI / model network | Run admission + `supervisedexec` bounds |
| `cap.network_github` | `gh` / GitHub API for issues, PRs, checks | Explicit run stage + host credentials outside DB |
| `cap.git_mutate` | Commit, branch, worktree add/remove | `gitutil` + worktree isolation + `writeexec` |
| `cap.process_control` | Spawn/kill supervised children | `supervisedexec` |
| `cap.native_delegate` | Provider-native sub-agents | Deny by default; only when attempt explicitly allows |
| `cap.ui_action` | Deliver reports / accept UI actions | UI protocol + ack verification (planned P2) |
| `cap.config_freeze` | Read effective policy after freeze | `internal/effectivepolicy` (V090-085) |
| `cap.machine_state` | Read/write machine.db facts | `internal/store` + future machine schema |
| `cap.project_state` | Read/write project.db events | `internal/store` + future project schema |

### Mapping common operations

| Operation | Required capability | Fail-closed if missing |
| --- | --- | --- |
| Open compact store | `cap.machine_state` or `cap.project_state` | Unsupported platform / permission error |
| Start worker provider | `cap.network_provider` + `cap.process_control` + frozen write or read-only mode | No launch |
| Nested read-only child | `cap.read_repo` | `readonlyexec` violation |
| Nested bounded write | `cap.bounded_write` + `cap.git_mutate` (limited) | `writeexec` violation |
| Push / open PR | `cap.network_github` + `cap.git_mutate` | No network side effect |
| Kill hung provider tree | `cap.process_control` | Leave needs-human rather than orphan kill without authority |
| Auto-select provider | none in v0.9 default path | Explicit pin required until router issues land |
| Provider-native sub-agent | `cap.native_delegate` | Denied unless attempt pin allows |
| UI “approve merge” action | `cap.ui_action` + human gate | Ignore forged ack |

## 5. Existing enforcement inventory

Reusable mechanics already in tree (review base `pre-prod`):

| Package | Boundary covered | Limits |
| --- | --- | --- |
| `internal/readonlyexec` | Child must not change repo/project authority surfaces | Evidence outside guarded paths; no OS sandbox |
| `internal/writeexec` | Isolated worktree + allowed path manifest; symlink escape detection | Parent dirt tolerated only outside allowed set |
| `internal/gitutil.CleanEnv` | Strips inherited `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_COMMON_DIR`, `GIT_NAMESPACE`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_CONFIG*` | Does not remove credential env vars (those must never be logged) |
| `internal/sanitize` | Redacts tokens, assignment secrets, and local paths in text | Pattern-based; not a complete DLP product |
| `internal/pathid` | Physical identity vs display path; symlink alias collapse | Identity is not a permission proof by itself |
| `internal/store` | Owner-only modes, symlink rejection, `darwin/arm64` gate | Foundation only; no domain tables yet |
| `internal/supervisedexec` | Hard caps, process groups, Darwin guardian hooks | Not a hypervisor |
| `internal/guardrails` | Budget-oriented guards | Complements, does not replace path policy |
| Evidence tiers (`V090-002`) | Keeps heavy scans remote; local pre-push stays small | Does not replace security job |

## 6. Threat catalog

| ID | Threat | Untrusted vector | Required control | Status |
| --- | --- | --- | --- | --- |
| T1 | Prompt injection alters route/permission | Issue body, provider output | Immutable effective-policy + route snapshot; content never writes pins | **Control: `effectivepolicy` (admission wiring still required on direct-run)** |
| T2 | Path escape from worktree | `../`, absolute paths | `writeexec` allowed paths + physical within check | Enforced in `writeexec` |
| T3 | Symlink swap to escape root | Symlink DB path or worktree entry | `store` open rejects symlink paths; `writeexec` symlink escape violations | Enforced for store + writeexec |
| T4 | Poisoned `GIT_*` env captures commits | Inherited environment | `gitutil.CleanEnv` on git exec | Enforced for `gitutil` client |
| T5 | Hook/config redirection | `.git/hooks`, git config mutation by child | `readonlyexec` / `writeexec` detect hook/config/ref/index changes | Enforced for nested sessions |
| T6 | Secret-shaped output leakage | Provider logs, reports | `sanitize.Text` before render/persist of free text | Partial; full field classification is this doc |
| T7 | Forged UI acknowledgement | Localhost bridge / spoofed client | Authenticated UI protocol + ack verification | **Gap → UI/P2 issues (`V090-012+`)** |
| T8 | Stale replay of side-effecting action | Recovered cursor, duplicate delivery | Idempotency keys + generation checks | **Gap → delivery/direct-run issues** |
| T9 | Stale authority after cancel | Orphan provider tree | `supervisedexec` / guardian | Partial on Darwin |
| T10 | Credential persistence | Env, files, transcripts | Class `credential` forbidden in store | Policy; scanners assist |
| T11 | Cross-project state mix-up | Path aliases | Registry project id + `pathid` | Planned machine/project stores |
| T12 | Optional bot as false gate | Greptile absence/failure | Required checks from `.delivery.yml` only | Enforced by evidence policy |

## 7. Threat fixtures (policy vectors)

Synthetic fixtures only. No real credentials, private repos, or provider calls.

| Vector | Existing consumer | Expected fail-closed signal |
| --- | --- | --- |
| Path escape (`../secret`) | `writeexec` allowed-path evaluation | `out_of_scope_mutation` / rejection |
| Symlink swap on store path | `store.Open` | error containing `symlink` |
| Poisoned `GIT_DIR` / `GIT_WORK_TREE` | `gitutil.CleanEnv` | Cleaned env; fixture commit stays in intended repo |
| Hook/config redirection | `readonlyexec` Finish | `git_hooks_modified` / `git_config_modified` |
| Secret-shaped output | `sanitize.Text` | `[REDACTED_*]` placeholders |
| Forged UI ack | *none yet* | Documented gap; must not be treated as merge authority |
| Stale replay action | *none yet on v0.9 path* | Documented gap; blocking for direct-run completion issues |

Executable vectors for APIs that exist today live in
`internal/securitypolicy` tests and reuse `gitutil`, `sanitize`, and `store`.

## 8. Unresolved gaps (blocking dependencies)

These are **not** declared safe by prose:

| Gap | Blocks | Follow-up |
| --- | --- | --- |
| Immutable effective-policy snapshot + provenance | Silent pin override by env/host | **Landed in `internal/effectivepolicy` (V090-085 / #1094)**; direct-run admission still must call it |
| Acceptance harness with fake provider/UI/GitHub | Cheap adversarial replay fixtures | **`V090-003` / #1095** |
| Authenticated UI ack and action receipts | Forged localhost progress/actions | P2 UI protocol issues |
| Full credential non-persistence proofs in every renderer | Residual log leakage | Audit + renderer issues under operations phase |
| v0.9 capability admission on `loopcoder run` | Capability only documented | Direct-run implementation issues after Gate R |

## 9. Non-goals

- Building an OS sandbox, container runtime, or endpoint security product.
- Reading, storing, or transforming provider credentials.
- Provider-specific safety policies beyond generic untrusted-output handling.
- Claiming that grepping secrets equals comprehensive DLP.

## 10. Verification

- Document review against `pre-prod` enforcement packages listed above.
- Focused tests: `go test ./internal/securitypolicy -count=1`
- Remote CI remains authoritative for repository-wide security job.
- All fixtures use synthetic paths and tokens only.
