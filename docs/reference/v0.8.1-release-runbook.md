# v0.8.1 Release Runbook

Operator checklist to take a frozen `pre-prod` candidate through **Full GO** and
public publication. Code harnesses for routing, installer PATH, canaries, Apple
sign/notarize, and the product-path gate are already on `pre-prod` (tracking
[#1002](https://github.com/jasonhnd/loopcoder/issues/1002)).

Supported tuple: **native macOS Apple Silicon (`darwin/arm64`) only**.

## Preconditions

| Item | Required? | Notes |
| --- | --- | --- |
| `pre-prod` green for the freeze SHA | Yes | Includes merged #1032–#1047 product/release work |
| GitHub env `release-publication` | Yes | Human reviewer for final publish |
| GitHub env `release-canary` | Yes (live canaries) | Required reviewers; trusted runner |
| Repo variable `APPLE_SIGN=1` | Optional (live Apple trust) | Without it, release sign job stays dry-run; product-path Full GO still allowed |
| Secrets `APPLE_CODESIGN_IDENTITY`, `APPLE_TEAM_ID`, `APPLE_NOTARY_KEYCHAIN_PROFILE` | Optional (live Apple) | Required only when claiming Gatekeeper-friendly public download signing |
| Authenticated `codex` + `claude` on canary runner | Yes (blocking live canaries) | |
| Optional `grok` / `agy` on canary runner | No | Non-blocking (#1021) |
| Developer ID cert + notarytool keychain profile on sign runner | Optional (live Apple) | Recommended for DMG/download UX; not required for CLI product-path GO |

## Phase 0 — Freeze

```bash
git fetch origin pre-prod
git rev-parse origin/pre-prod   # record CANDIDATE_SHA
# Confirm open release-blockers: only #1002 tracking should remain
gh issue list --repo jasonhnd/loopcoder --label release-blocker --state open
```

Record:

```text
CANDIDATE_SHA=
TAG=v0.8.1
```

Do not land further product PRs on the freeze SHA.

## Phase 1 — Deterministic fixture gate (any macOS arm64 host)

```bash
git checkout "$CANDIDATE_SHA"
bash scripts/v081-product-path-gate.sh \
  --mode fixture \
  --candidate-sha "$CANDIDATE_SHA" \
  --artifact-dir ./gate-fixture
# Expect decision=GO (live steps not_run)
```

If fixture is NO-GO, stop and fix code; do not tag.

## Phase 2 — Build one candidate binary (same bytes everywhere)

Prefer the release workflow tag path. For a local dry build:

```bash
version=0.8.1
CGO_ENABLED=0 go build -trimpath \
  -ldflags "-s -w -X main.version=${version} -X main.commit=${CANDIDATE_SHA} -X main.date=$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  -o ./loopcoder ./cmd/loopcoder
./loopcoder version   # must show platform=darwin/arm64, not version=dev
DIGEST=$(shasum -a 256 ./loopcoder | awk '{print $1}')
echo "BINARY_DIGEST=$DIGEST"
```

## Phase 3 — Packaged product-path gate

```bash
bash scripts/v081-product-path-gate.sh \
  --mode packaged \
  --binary ./loopcoder \
  --expected-digest "$DIGEST" \
  --candidate-sha "$CANDIDATE_SHA" \
  --artifact-dir ./gate-packaged
# Expect decision=GO; nested matrix + CLI probes pass
```

## Phase 4 — Blocking live canaries (Codex + Claude)

On a machine/runner with authenticated CLIs and env `release-canary` approval:

```bash
# Or dispatch: Actions → "Release provider canaries" → mode=live
LOOPCODER_REAL_PROVIDER_CANARY=1 bash scripts/release-provider-canary.sh \
  --mode live --provider codex --binary ./loopcoder \
  --expected-digest "$DIGEST" --candidate-sha "$CANDIDATE_SHA" \
  --timeout-seconds 180 --max-calls 1 --artifact-dir ./canary-evidence

LOOPCODER_REAL_PROVIDER_CANARY=1 bash scripts/release-provider-canary.sh \
  --mode live --provider claude --binary ./loopcoder \
  --expected-digest "$DIGEST" --candidate-sha "$CANDIDATE_SHA" \
  --timeout-seconds 180 --max-calls 1 --artifact-dir ./canary-evidence
```

Both must `status: passed`. Do **not** accept test-subprocess or the other
provider as a substitute.

Optional non-blocking:

```bash
LOOPCODER_REAL_PROVIDER_CANARY=1 bash scripts/release-provider-canary.sh \
  --mode live --provider grok --binary ./loopcoder ...
LOOPCODER_REAL_PROVIDER_CANARY=1 bash scripts/release-provider-canary.sh \
  --mode live --provider antigravity --binary ./loopcoder ...
# not_available is OK; must not block GO
```

## Phase 5 — Live Apple trust (optional / recommended)

Live Developer ID + notarize is **not** required for product-path Full GO.
Publish without it when the distribution model is CLI/source/Homebrew-style
(Sigstore + checksums). Run this phase when you want Gatekeeper-friendly
download UX comparable to a notarized desktop app.

With `APPLE_SIGN=1` and secrets configured (or local keychain profile):

```bash
APPLE_SIGN=1 \
APPLE_CODESIGN_IDENTITY="Developer ID Application: …" \
APPLE_TEAM_ID=XXXXXXXXXX \
APPLE_NOTARY_KEYCHAIN_PROFILE=loopcoder-notary \
bash scripts/macos-codesign-notarize.sh \
  --mode live \
  --binary ./loopcoder \
  --archive ./loopcoder_0.8.1_darwin_arm64.tar.gz \
  --artifact-dir ./apple-evidence
```

Then regenerate checksums **only on final bytes** (signed archive if you signed):

```bash
shasum -a 256 loopcoder_0.8.1_darwin_arm64.tar.gz | awk '{print $1 "  " $2}' > SHA256SUMS
# cosign sign-blob SHA256SUMS --bundle SHA256SUMS.sigstore --yes
# cosign verify-blob … (release workflow identity)
```

Digest immutability: the archive SHA used by canaries after re-sign must match
the published draft assets. If you skip Apple live, freeze the **unsigned**
candidate digest used in Phase 4 canaries.

## Phase 6 — Full GO command (single evidence bundle)

Product-path Full GO (blocking):

```bash
bash scripts/v081-product-path-gate.sh \
  --mode packaged \
  --binary ./loopcoder \
  --expected-digest "$DIGEST" \
  --candidate-sha "$CANDIDATE_SHA" \
  --include-live-canaries 1 \
  --artifact-dir ./gate-full
```

Optional Apple live on the same digest (when Developer ID is available):

```bash
bash scripts/v081-product-path-gate.sh \
  --mode packaged \
  --binary ./loopcoder \
  --expected-digest "$DIGEST" \
  --candidate-sha "$CANDIDATE_SHA" \
  --include-live-canaries 1 \
  --include-apple-live 1 \
  --artifact-dir ./gate-full-apple
```

**Product-path GO** if:

1. `v081-go-no-go-evidence.json` has `"decision": "GO"`
2. Blocking live Codex/Claude canaries passed
3. Zero open `release-blocker` issues except this tracking epic after publication
4. README / capability matrix match observed behavior

**Optional for GO (recommended for public download UX):**

5. Live Apple trust passed when `--include-apple-live 1` was requested, or the
   release workflow live sign job succeeded for the published archive

**NO-GO**: leave the GitHub Release as **draft**; do not make latest; fix one
narrow blocker with owner approval. Missing Apple credentials alone is **not**
product-path NO-GO.

## Phase 7 — Tag and release workflow

```bash
# After GO evidence is retained locally/as artifacts
git tag -a v0.8.1 -m "v0.8.1" "$CANDIDATE_SHA"
git push origin v0.8.1
# Release workflow: build → apple dry-run or live sign → cosign → draft → smoke → publish env
```

Confirm:

- Draft assets: only `loopcoder_0.8.1_darwin_arm64.tar.gz`, `SHA256SUMS`, `SHA256SUMS.sigstore`
- Smoke nested permission matrix on packaged binary
- Human approval on `release-publication`
- Post-publish: download archive, verify checksum + cosign, `loopcoder version`

## Phase 8 — Close tracking

After public verification:

1. Attach gate evidence paths/run URLs on [#1002](https://github.com/jasonhnd/loopcoder/issues/1002)
2. Close #1002 and the `v0.8.1 Production Closure` milestone if used
3. Do not rewrite the historical [v0.8.0 go/no-go](v0.8.0-go-no-go.md)

- Do not re-open the full product roadmap during release.
- Do not treat fixture or dry-run success as live Codex/Claude canaries.
- Do not treat missing Apple Developer ID as product-path Full GO failure.
- Do not publish Windows/Linux/Intel assets for v0.8.1.
