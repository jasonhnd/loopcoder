# v0.9.0 quickstart (V090-080 / #1321)

Issue: [#1321](https://github.com/jasonhnd/loopcoder/issues/1321)

**Public release status:** The current published product release remains
**v0.8.1** until an owner GO publishes v0.9.0. Commands below describe the
**pre-prod / candidate** surface and must be run against a built candidate
archive (or source build of `pre-prod`), not assumed to exist on the public
release channel.

## Install (Darwin arm64 only)

```bash
# Prefer the exact RC archive from the protected Release Candidate Draft workflow
# (workflow_dispatch on pre-prod SHA). Do not treat source-build as release proof.
# Placeholder (not a public URL until owner publishes):
#   tar -xzf loopcoder_<version>_darwin_arm64.tar.gz
#   ./loopcoder version

# Development build from a clean worktree (not qualification evidence):
go build -o loopcoder ./cmd/loopcoder
./loopcoder version
```

Platform: **darwin/arm64 only**. Other hosts are unsupported for v0.9 product.

## First run (read-only)

```bash
loopcoder doctor
loopcoder doctor --format json
loopcoder capabilities --format json
loopcoder diagnose --project-id <project-id> --dry-run --format json
```

## Ordinary development (not self-bootstrap)

v0.9 ordinary development does **not** use `loopcoder compile`, `dispatch`, or
`tick` against the LoopCoder repository. Use:

1. Isolated worktree / branch from `pre-prod`
2. Implement **one** issue
3. PR with required checks: verify / test / race / security
4. Merge + exact-SHA `integration-verify` + `integration-canary` dual green
5. Human merge gate for production (no auto-merge)

## Primary product commands (executed help-aligned)

```bash
# Explicit route pin (never overridden)
loopcoder run --repo <path-or-owner/name> --issue <n> \
  --provider <p> --model <m> --format json

# Auto-route / omitted provider+model (P4 enabled on candidate)
loopcoder run --repo <path-or-owner/name> --issue <n> --auto-route --format json
loopcoder run --repo <path-or-owner/name> --issue <n> --dry-run --format json

# Bounded workflow (human gate)
loopcoder workflow run --fixture one --format json
loopcoder workflow run --fixture chain --format json

# Visibility
loopcoder status --repo <path> --format json
loopcoder events --repo <path>
loopcoder cancel --help   # see command help for run-id flags
loopcoder resume --help

# Providers / route explain
loopcoder providers --help
loopcoder route --help

# Migration (v0.8 → v0.9)
loopcoder migrate export-v08 --export-dir /tmp/v08-export --fixture --format json
loopcoder migrate import-v09 --export-dir /tmp/v08-export --format json          # dry-run
loopcoder migrate import-v09 --export-dir /tmp/v08-export --apply --format json  # apply
# aliases: loopcoder export-v08 / loopcoder import-v09

# Support / qualification
loopcoder diagnose --project-id <id> --dry-run --format json
loopcoder diagnose --project-id <id> --archive --output /tmp/bundle --format json
loopcoder qualify --archive dist/loopcoder_*.tar.gz --digest <sha256> --format json
```

## UI protocol note

Reports use the transport-neutral `loopcoder.ui.v1` projection. Terminal JSONL
and optional loopback bridge are product surfaces. **Paseo is an external
client**, not a LoopCoder dependency.

## Storage and privacy

- Global/project stores under `$LOOPCODER_HOME` — **no** production writes to
  customer `<repo>/.loopcoder`
- Private content redacted per privacy policy
- Cross-Mac: terminal GitHub rehydration only — no live DB merge / lease fleet
- Support bundles: local only; telemetry disabled; no network upload

## Unsupported (honest)

| Path | Status |
| --- | --- |
| Autonomous `compile` / `tick` / `trigger` as product path | unsupported for ordinary LoopCoder self-dev |
| Federation / nested production ownership | unsupported |
| Cross-Mac live lease / DB merge | unsupported |
| Repo-local runtime sidecars | unsupported |
| v0.8 storage mutation from the v0.9 binary | unsupported |
| Non-darwin/arm64 product platform | unsupported |
| Auto-merge | unsupported (human gate default) |

See [capability matrix](v0.9.0-capability-matrix.md) and
`loopcoder capabilities --format json` for authoritative rows.
