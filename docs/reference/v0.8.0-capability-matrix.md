# v0.8.0 Capability And Support Matrix

This is the binding user-facing support statement for the immutable v0.8.0
release. It distinguishes code inventory from reachable product behavior and
from production evidence.

The `v0.8.0` tag and published artifacts remain unchanged. The release passed
its documented publication, integrity, migration, and deterministic smoke
gates. A later product-path audit found that several advertised orchestration
capabilities were implemented as libraries, schemas, or fixture-tested paths
without being fully connected to the shipped commands or proven with the exact
artifact and real providers. Therefore, use v0.8.0 for controlled canary and
development work; do not treat it as an end-to-end production-closure release.

The bounded follow-up is tracked by
[#1002](https://github.com/jasonhnd/loopcoder/issues/1002). This document does
not move the v0.8.0 tag, replace its assets, or retroactively change its release
evidence.

## How To Read The Matrix

- **Implemented** means code, schemas, or adapter declarations exist. It does
  not by itself prove that a user can reach the behavior safely.
- **Reachable product entry point** names the shipped command or host path. A
  missing entry point means the capability is not a v0.8.0 product feature.
- **Deterministic integration coverage** identifies fixture or subprocess
  evidence. Synthetic coverage is not real-provider evidence.
- **Real-provider evidence** is limited to an actual provider invocation. Old
  mechanism smokes do not become exact-v0.8.0 release canaries.
- **Production support status** is the operative support decision. `Canary`
  means the path may be useful under direct human control but is not approved
  for unattended production orchestration.
